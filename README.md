# MIRO SmartHome (미로 스마트홈) — Home Assistant 통합

미로(MIRO) 기기를 SmartThings 경유 없이 Home Assistant에 직접 연동합니다.
미로 스마트홈 앱(`com.miro.mirotapp`)이 쓰는 비공식 클라우드 API를 그대로 사용합니다.

> **⚠️ 먼저 — 어느 앱으로 기기를 등록하셨나요?**
>
> 미로는 앱을 **두 개** 운영합니다. 기기에 따라 등록되는 앱이 다릅니다.
>
> | 앱 | 플랫폼 | 지원 |
> | --- | --- | --- |
> | **미로 스마트홈** | 미로 자체 (miroT) | ✅ **이 통합의 대상입니다** |
> | **미로 홈링크** | Tuya | ❌ 지원하지 않습니다 |
>
> 계정도 서버도 서로 완전히 다릅니다. 한쪽 앱에 등록한 기기는 다른 앱에 보이지 않고,
> 계정도 공유되지 않습니다. 어느 쪽이 상위 버전이거나 후속인 관계가 아니라 **그냥 별개**입니다.
>
> 폰에서 앱을 열어 **그 기기가 미로 스마트홈 안에 보이는지** 확인하고, 보이면 그 계정을 쓰시면 됩니다.
> 홈링크 쪽에 있다면 HA의 Tuya 통합이나 `tuya-local` 을 알아보세요.

SmartThings 연동에서 풍량 4단계·회전 2종으로 뭉개지던 것과 달리,
**풍량 1~100단계, 회전각 0/30/60/90/120도**를 그대로 씁니다.

> 미로가 공식 지원하는 통합이 아닙니다. 앱을 분석해 알아낸 API를 쓰므로
> 미로 측 변경으로 언제든 동작하지 않을 수 있습니다.

## 지원 기기

앱 서버가 내려주는 기기 정의를 그대로 표로 만들어(`models.json`) 쓰기 때문에,
아래 27종의 제어 값 범위는 추측이 아니라 **공식 앱과 동일**합니다.

| 분류 | 모델 | HA 엔티티 |
| --- | --- | --- |
| 선풍기 | MF01, MF02, **MF03**, MAF01 | `fan` |
| 서큘레이터 | MC01 | `fan` |
| 공기청정기 | MP500G, MP600G, MPUV20, MPUV24, AP500, OSHS01, MP1000~1003 | `fan` |
| 가습기 | NR07, NR08, NR10, AR05, MH5000, MH7000, MH8K, MH9K | `humidifier` |
| 디퓨저 | DF01, DIF01, DIF02 | `switch` + `select` |
| 센서 | RD01 | `switch` + 센서 |

공기청정기를 `fan` 으로 만드는 것은 Home Assistant의 관례입니다.

### 검증 수준 — 꼭 읽어주세요

| 상태 | 대상 |
| --- | --- |
| **실기기로 검증** | **MF03** (선풍기) — 전원·풍량·회전·모드 제어, 온습도·배터리 상태<br>**NR07** (가습기) — 전원 제어, 분무 세기 자동 전환, 물부족 감지 |
| 정의만 검증 | 나머지 25종 — 서버 메타데이터와 실제 기기 정의(`feature`)로 엔티티 구성까지 확인했으나, **실기기에 명령을 보내보지는 못했습니다** |

선풍기와 가습기가 **완전히 같은 API로 동작하는 것을 확인**했으므로, 같은 구조인
공기청정기·서큘레이터·디퓨저도 동작할 가능성이 높습니다. 다만 보증할 수는 없습니다.
문제가 있으면 이슈로 알려주시면 고치겠습니다.

## 만들어지는 엔티티

기기가 실제로 보고하는 기능 목록(`feature`)과 모델 표를 겹쳐서 만듭니다.
**모델에 없는 기능은 엔티티도 생기지 않습니다.**

| 엔티티 | 예시 |
| --- | --- |
| `fan` | 전원, 풍량, 운전 모드, 좌우 회전 |
| `humidifier` | 전원, 운전 모드, 현재 습도 |
| `sensor` | 온도, 습도, **배터리 잔량**, 미세먼지, 가스, CO₂, 조도, 필터 잔량, 타이머 남은 시간 |
| `binary_sensor` | **충전 중**, 배터리 장착, 물 부족, 필터 교체, 연결 상태 |
| `select` | 회전 범위, 타이머, 분무 세기, 조명, 밝기, 향, 분사 단계 등 |
| `switch` | 차일드락, 소리, 자외선 살균, 상하 회전 등 |

일부 엔티티(타이머 남은 시간, 배터리 장착, 연결 상태)는 기본 비활성입니다.
필요하면 기기 페이지에서 켜세요.

### 일부러 만들지 않는 것

값 체계를 확실히 모르는 항목은 **추측해서 명령을 보내지 않습니다.**
대신 설치 시 로그에 무엇을 건너뛰었는지 남깁니다.

- MF03의 쾌적 모드 상세 설정 (`Bias`, `FanSpeedHigh/Low`, `SensorTemperature/Humidity`)
- 가습기의 목표 습도 임계값 (`HumidityRule1~3`)
- NR08의 조명 끄기 (`LightMode` — 켜는 값을 앱 정의에서 확인할 수 없음)

## 설치

### HACS

1. HACS → 우측 상단 ⋮ → **Custom repositories**
2. 이 저장소 주소를 넣고 종류는 **Integration** 선택
3. 목록에서 `MIRO SmartHome` 설치
4. **Home Assistant 재시작**

### 직접 복사

`custom_components/mirot/` 폴더를 HA 설정 디렉터리의 `custom_components/` 아래로
복사한 뒤 재시작합니다.

## 설정

**설정 → 기기 및 서비스 → 통합 추가 → MIRO SmartHome**

미로 스마트홈 앱에서 쓰는 **아이디와 비밀번호**를 입력하면 기기를 자동으로 찾습니다.

통합 카드의 **설정**에서 상태 확인 주기를 바꿀 수 있습니다(기본 5초, 5~300초).

## 동작 방식

### 조작하면 언제 HA에 반영되나요

| 어디서 조작했나 | HA에 뜨기까지 |
| --- | --- |
| **HA에서** (대시보드·자동화) | 즉시 |
| **리모컨·본체 버튼** — 기기가 켜져 있을 때 | 10초 안팎 |
| **리모컨·본체 버튼** — 기기가 다 꺼져 있을 때 | 20~30초 |

"기기가 켜지면 ~한다" 같은 자동화를 만드신다면 마지막 줄을 감안하세요.
리모컨으로 켜는 경우 그만큼 늦게 걸립니다.

### 왜 그런가요

미로 서버에는 상태가 바뀌었다고 HA에 알려주는 기능이 없습니다. HA가 주기적으로
물어봐야 합니다.

다행히 **기기는 조작을 받으면 몇 초 안에 서버로 알려줍니다.** 그래서 리모컨으로
만져도 HA가 따라올 수 있습니다. 다만 HA가 다음번 물어볼 때까지는 모르니, 그
기다리는 시간이 위 표의 차이입니다.

**기기가 다 꺼져 있으면 천천히 물어봅니다.** 볼 게 없는데 자주 물어봐야 미로
서버에 요청만 늘기 때문입니다. 하나라도 켜지면 곧바로 빨라집니다.

온도·습도·배터리는 조작과 상관없이 알아서 변하는 값이라, 이건 **1분에 한 번**
따로 확인합니다.

확인 주기를 길게 잡으시면 위 표의 시간도 그만큼 늘어납니다.

### 잠깐 안 될 때는 기다립니다

무선 기기라 서버가 기기에 물어봤는데 답이 없는 경우가 가끔 있습니다.
그럴 때 엔티티를 바로 `unavailable` 로 떨구지 않고 **직전 값을 유지**합니다.
세 번 연속 실패해야 사용 불가로 바뀝니다. 한 번 늦었다고 화면이 깜빡이지
않습니다.

## 알아둘 점

- **풍량을 바꾸면 꺼져 있던 기기가 켜집니다.** 기기 동작이 그렇습니다.
- **자동·자연·수면 모드에서는 풍량을 직접 못 바꿉니다.** 통합이 알아서
  수동 모드로 먼저 전환한 뒤 풍량을 적용합니다.
- 회전 범위를 0이 아닌 값으로 두면 회전이 켜지고, 0이면 꺼집니다. 기기에서 연동됩니다.
- **가습기는 전원을 켜면 분무 세기가 자동으로 "약"이 됩니다.** 세기를 따로 지정할 필요 없습니다.
- **물 부족(`EmptyWater`)은 동작 중에만 뜹니다.** 전원을 끄면 물이 없어도 해제되므로,
  알림 자동화를 만들 때 이 점을 감안하세요.
- 온도·습도 센서가 값을 안 보내는 기종이 있습니다. NR07 가습기는 온습도 센서가
  **무선 리모컨(미로컨)에 달려 있어**, 리모컨이 값을 안 올리면 해당 엔티티가
  `unavailable` 로 남습니다.
  - **온도·습도·배터리가 한꺼번에 `unavailable` 이면 미로컨을 보세요.**
    가습기는 배터리로 돌지 않습니다. 그 배터리 센서는 본체가 아니라 **미로컨 배터리**입니다.
    셋이 같은 출처라 함께 죽습니다. 미로컨 배터리 교체, **세워 두기**(눕히면 보고하지 않습니다),
    페어링 순으로 확인하세요.
  - 반대로 분무 세기·타이머·물 부족처럼 **본체가 보내는 값이 멀쩡하면 통합은 정상**입니다.
    미로 스마트홈 앱에서도 온습도가 안 보인다면 기기 쪽 문제입니다.
- 인터넷 연결이 끊긴 기기는 엔티티가 `unavailable` 로 표시됩니다.
- 표에 없는 새 모델을 쓰면 On/Off와 센서만 만들어집니다.
  `python3 tools/gen_models.py --download` 로 표를 갱신할 수 있습니다.
- 통합 아이콘은 **Home Assistant 2026.3 이상**에서만 보입니다. 그 아래 버전에서는
  `icon not available` 로 남지만 동작에는 아무 영향이 없습니다.

## 도구

- [tools/miro_cli.py](tools/miro_cli.py) — HA 없이 API를 직접 확인하는 CLI.
  문제가 통합 쪽인지 서버 쪽인지 가릴 때 씁니다. **이슈에 붙일 출력을 이걸로 뽑습니다.**
- [tools/gen_models.py](tools/gen_models.py) — 서버 메타데이터에서 모델 표를 생성.

```bash
pip3 install requests cryptography
python3 tools/miro_cli.py login
python3 tools/miro_cli.py devices
python3 tools/miro_cli.py status
```
